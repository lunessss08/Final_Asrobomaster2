# Asrobo2 — RoboMaster EP

โปรแกรม Python สำหรับเล็งยิงเป้าสี และสำรวจเขาวงกตก่อนเดินไปยิงเป้า
แยกโค้ดตามหน้าที่ โดยเก็บไฟล์เริ่มต้นและคำสั่งรันเดิมไว้

## โครงสร้างไฟล์

```text
Asrobo2/
├── gimbalshoot.py          # เริ่มโปรแกรมเล็งยิง / calibrate สี
├── maze_shooter.py         # เริ่มโปรแกรมเขาวงกต / โหมดจำลอง
├── robo_app/
│   ├── aim/               # ระบบเล็งยิงและส่วนที่เขาวงกตใช้ร่วมกัน

│   │   ├── color_config.py # HSVRange และอ่าน/บันทึก autoaim_config.json
│   │   ├── helpers.py     # เรียก SDK อ่านภาพ แปลงพิกเซลเป็นมุม
│   │   ├── blind_zones.py # พื้นที่ที่ไม่ตรวจจับเป้า / ลากกรอบด้วยเมาส์
│   │   ├── vision.py      # เตรียมภาพ ตรวจจับสี และกรองรูปร่างป้าย

│   │   ├── leds.py        # ควบคุมไฟ LED

│   │   ├── app.py         # หน้าจอ calibrate/ready/mission และเชื่อมต่อหุ่น
│   │   └── cli.py         # รับ argument และเริ่มแอป
│   └── maze/
│       ├── settings.py    # ขนาดช่อง การเดิน เซ็นเซอร์ และค่าภารกิจ
│       ├── errors.py      # ข้อยกเว้นเมื่อหยุดหรือฮาร์ดแวร์ผิดพลาด
│       ├── mapping.py     # MazeMap, Dijkstra รอบสำรวจ, A* รอบยิง, และ JSON
│       ├── vision.py      # ตรวจรูปทรงเป้าและคำนวณมุม
│       ├── hardware.py    # หุ่นจริง ToF และ Sharp IR ซ้าย/ขวา
│       ├── simulation.py  # หุ่นจำลอง สนาม 4×4 และภาพกล้องจำลอง
│       ├── camera.py      # thread อ่านภาพกล้อง
│       ├── mission.py     # สำรวจ บันทึกเป้า เดินตามเส้นทาง และยิง
│       ├── ui.py          # ภาพกล้อง แผนที่ ปุ่ม และคีย์บอร์ด
│       └── cli.py         # ตั้งค่าสนาม รับ argument และเริ่มแอป
├── sdk-support/            # ไลบรารีถอดรหัสภาพ/เสียงสำหรับ RoboMaster SDK
└── tests/
    └── test_refactor.py    # ทดสอบโมดูลร่วมกันโดยไม่ต่อหุ่น
```

`__init__.py` ในแต่ละแพ็กเกจรวม public API เพื่อให้ import ผ่านไฟล์เดิมได้
เช่น `import gimbalshoot as gs` และ `import maze_shooter`
โมดูลภายในใช้ explicit imports เพื่อให้เห็นว่าแต่ละส่วนพึ่งพาอะไร

## วิธีรัน

รันจากโฟลเดอร์ Asrobo2 โดยใช้ environment เดิม:

```bash
source .venv/bin/activate
python gimbalshoot.py --calibrate   # ปรับค่าสีและพื้นที่ตาบอด
python gimbalshoot.py               # เล็งยิงกับหุ่นจริง
python maze_shooter.py --sim        # จำลองสนาม 4×4 บนคอม
python maze_shooter.py              # สำรวจและยิงกับหุ่นจริง
python maze_shooter.py --load       # โหลดแผนที่เพื่อสำรวจต่อหรือทำรอบยิง
```

ต้องมี OpenCV, NumPy และ RoboMaster SDK แม้ใช้โหมดจำลอง
หน้าจอใช้ OpenCV และต้องรันใน environment ที่เปิดหน้าต่างได้

สนามจริงตั้งค่าเริ่มต้นเป็น 6×6 ช่อง (ช่องละ 60 ซม.) กด Enter ตอนถาม
ความกว้างและความยาวเพื่อใช้ขนาดนี้ โหมด `--sim` ยังเป็นสนามตัวอย่าง 4×4
ส่วน `--load` ใช้ขนาดจากไฟล์แผนที่เดิม หากไม่รู้ช่องเริ่มต้น โปรแกรมจะใช้
ตารางเผื่อ 11×11 สำหรับสนามจริง 6×6 เพื่อรองรับจุดเริ่มที่ไม่ทราบตำแหน่ง

รอบเขาวงกต: `e` สำรวจพร้อมยิงตามสี/รูปทรงที่เลือก, `m` สำรวจอย่างเดียว,
`4` เปลี่ยนสี, `5` เปลี่ยนรูปทรง, `f` จบรอบสำรวจ, `Enter` เริ่มรอบยิง,
`d` ซ้อมโดยไม่ยิง, `x`/Space หยุด และ `q`/Esc ออก
หน้าเล็งยิงใช้ `r/g/b/y` เลือกลำดับสี, `Enter` เริ่มยิง, `d` ซ้อม
และ `t` เข้าหน้าปรับค่าสี

## แก้โค้ดที่ไหน

- ปรับความเร็ว ระยะ และเกณฑ์เซ็นเซอร์: `robo_app/maze/settings.py`
- ปรับ PID เกณฑ์ล็อกเป้า หรือค่าสีเริ่มต้น: `robo_app/aim/settings.py`
- ปรับการจับเป้า: `robo_app/aim/vision.py`
- ปรับเส้นทาง Dijkstra รอบสำรวจหรือ A* รอบยิง: `robo_app/maze/mapping.py`
- ปรับขั้นตอนสำรวจและยิง: `robo_app/maze/mission.py`
- ปรับหน้าจอ: `robo_app/aim/app.py` หรือ `robo_app/maze/ui.py`

ไฟล์ข้อมูลยังอยู่ที่รากโปรเจกต์เช่นเดิม: `autoaim_config.json`,
`maze_map.json`, `sensor_map.json` และ `logs/` ไม่ย้ายตามโมดูล
ไฟล์เหล่านี้สร้างหรือบันทึกเมื่อใช้งานจริง และอาจยังไม่มีในโฟลเดอร์
เมื่อโหลดโปรแกรมเขาวงกต จะขยายเกณฑ์ขนาดเป้าใน `aim.settings`
เพื่อรองรับเป้าที่อยู่ใกล้กล้องเหมือนโค้ดเดิม

## ตรวจสอบ

```bash
python -m unittest discover -s tests -v
python -m compileall -q robo_app gimbalshoot.py maze_shooter.py
python gimbalshoot.py --help
python maze_shooter.py --help
```

ชุดทดสอบตรวจตำแหน่งไฟล์ข้อมูล การหาเส้นทางและบันทึกแผนที่
ภาพจำลองกับระบบตรวจจับเป้า เกณฑ์เป้าที่ปรับร่วมกัน การวาดหน้าจอจำลอง
และค่าเริ่มต้นของตัวควบคุม โดยไม่เชื่อมต่อหรือสั่งงานหุ่นจริง

## การหยุดและการยืนยันสถานะ

- STOP ปิดการยิงและส่งคำสั่งหยุดล้อ/กิมบอลทันที งานที่รอคำสั่ง SDK
  ตรวจ STOP ระหว่างรอและตรวจว่าคำสั่งสำเร็จจริงก่อนทำขั้นต่อไป
  เวลาที่หุ่นหยุดจริงยังขึ้นกับการส่งคำสั่งผ่าน Wi-Fi และการตอบสนองของหุ่น
- หากหยุดระหว่างเดิน/เลี้ยว หรือคำสั่งถอย/คืนตำแหน่งล้มเหลว
  โปรแกรมจะถือว่าตำแหน่งไม่แน่นอน ให้วางหุ่นที่ START หันทิศเดิมแล้วกด `h`
- การตรวจ START ต้องอ่าน ToF ได้ครบทุกทิศที่แผนที่มีข้อมูล หากอ่านไม่ครบ
  จะไม่อนุญาตให้เริ่มจากตำแหน่งนั้น แผนที่ใหม่ที่ยังไม่มีข้อมูลรอบ START
  ยังต้องอาศัยผู้ใช้วางหุ่นให้ถูก และผนังที่สมมาตรไม่สามารถยืนยันทิศได้แน่นอน
- รอบยิงเขาวงกตตรวจรูปทรงให้ตรงกับแผนที่ด้วย หากรูปทรงในแผนที่เป็น `?`
  จะใช้การตรวจสีตามเดิม เป้ากระโดดหรือขนาดเปลี่ยนมากจะเริ่มนับเวลาล็อกใหม่
  ปรับเกณฑ์ได้ที่ `AIM_TRACK_JUMP_DEG` และ `AIM_TRACK_AREA_RATIO`
- ภาพขาดช่วง/เป้าหาย/เล็งหลุดจะเริ่มนับเวลาล็อกใหม่ ไม่สะสมเวลาจากภาพเดิม

ค่าเรขาคณิตกล้องและระยะเป้ายังต้องสอบเทียบกับสนามจริงก่อนปรับ
ชุดทดสอบกรณี STOP, SDK ล้มเหลว, ToF ขาด และการยืนยันเป้าอยู่ใน
`tests/test_mission_reliability.py`

## แผนที่และหลายเป้าต่อช่อง (เวอร์ชัน 2)

- ระบบติดตามป้ายแต่ละแผ่นแยกกัน แม้สีเดียวกันและอยู่ช่องเดียวกัน
  ต้องพบแผ่นนั้นอย่างน้อย 3 จาก 5 เฟรม ไม่รวมคะแนนจากป้ายสีเดียวกันคนละแผ่น
- ก่อนบันทึกเป้าบนผนังของช่องปัจจุบัน จะตั้งหัวตรงแล้ววัด ToF ยืนยันผนัง
  การเห็นป้ายเพียงอย่างเดียวไม่สร้างกำแพง หาก ToF อ่านไม่ได้จะหยุดให้ตรวจเซ็นเซอร์
  ทิศที่ยืนยันว่าเปิดจะไม่ก้มตรวจป้ายในช่องถัดไป
- แผนที่แสดงจำนวนแผ่นในช่องที่มีหลายเป้า คลิกช่องนั้นใน PICK ORDER
  เพื่อเล็ง/ยิงทุกแผ่นในช่องนั้นทีละแผ่น ผลแต่ละแผ่นบันทึกใน `plate_results`
- การเดินต้องมี odometry ใหม่ต่อเนื่อง และระยะเมื่อหยุดต้องห่างจาก
  60 ซม. ไม่เกิน `CELL_ARRIVAL_TOL_M` (เริ่มต้น 2 ซม.) มิฉะนั้นหยุดและถือว่าตำแหน่งไม่แน่นอน
- แผนที่รุ่นเก่ามีผนังที่อนุมานจากป้ายและอาจระบุเป้าผิด จึงไม่ใช้ `--load`
  กับแผนที่ที่มีเป้าแต่ยังไม่มีข้อมูลยืนยันผนัง ให้รัน `python maze_shooter.py`
  สำรวจใหม่ การเซฟรอบใหม่จะเขียนทับ `maze_map.json` โดยไม่สร้างไฟล์สำรอง
- Log ใหม่เก็บภาพต้นฉบับ `_raw.jpg` เพิ่มจากภาพที่วาดกรอบ และบันทึก
  `wall_check` เพื่อเทียบผลกล้องกับระยะ ToF ได้โดยไม่ต้องคาดเดาจากภาพ

## สำรวจพร้อมยิงเป้าที่เลือก

ค่าเริ่มต้นใน GUI คือ `COLOR: RED` และ `SHAPE: CIRCLE`:

1. คลิกสีและรูปทรงที่ต้องการได้โดยตรง (ตัวเลือกที่เลือกจะมีกรอบเน้น) หรือกด `4` / `5` เพื่อวนตัวเลือก
   `ANY` หมายถึงไม่จำกัดเงื่อนไขด้านนั้น เช่น RED + ANY ยิงสีแดงทุกทรง
   หรือ ANY + CIRCLE ยิงวงกลมทุกสี หากทั้งคู่เป็น ANY ปุ่มสำรวจพร้อมยิง
   จะให้เลือกเงื่อนไขก่อนเริ่ม
2. กด `e` / EXPLORE+FIRE หุ่นเดินสำรวจและบันทึกเป้าทุกชนิด
   SLAM ยังวัด ToF แนวระดับครบ 4 ทิศ; กล้องตรวจป้ายเฉพาะทิศที่มีผนังในช่องปัจจุบัน
   โดยข้ามทิศหลัง แล้วก้มต่อเนื่อง
   จากระดับ 0° ถึง −20° ด้วยความเร็ว 90°/วินาที ก่อนเก็บภาพใหม่ที่ −20°, −15°, −10°, −5° และ 0° ระหว่างยกกลับ
   การหัน gimbal ใช้ 300°/วินาที ส่วนการก้ม–ยกยังใช้ 90°/วินาที
   เมื่อยืนยันป้ายที่ตรงทั้งสีและรูปทรงพร้อมผนังด้วย ToF
   หุ่นจะล็อกเล็งด้วยกล้องและสั่งยิงน้ำ 3 นัดต่อป้ายแบบรัวในคำสั่งเดียว
   บนผนังของ **ช่องที่หุ่นยืนอยู่เท่านั้น** จำนวนที่ยิงไปแล้วจะบันทึกลงแผนที่ทันที
   หากโหลดแผนที่ที่บันทึกว่ายิงไป 1–2 นัด ระบบจะยิงเฉพาะนัดที่ยังขาด
   ช่องทางเปิดจะยังไม่ตรวจป้ายที่ผนังไกลของช่องถัดไป; เมื่อหุ่นเข้าไปถึง
   จึงตรวจผนังในช่องนั้นและยิงจากช่องเดียวกับเป้า
   ระหว่าง EXPLORE + FIRE หากแผนที่มีป้ายที่ตรงฟิลเตอร์และมีทางเปิด
   ระบบจะไปช่องเป้านั้นก่อนช่องว่างอื่น การเห็นป้ายเดียวกันจากหลายมุมก้มจะรวมเป็นป้ายเดียว
   หลังจากนั้นจะเข้าทุกช่องที่แผนที่ยืนยันว่ามีทางเปิดไปถึง รวมถึงช่องเป้าที่สำรวจขอบครบแล้ว
   โปรแกรมบันทึกความคืบหน้าลง `maze_map.json` ไฟล์เดียวและเขียนทับไฟล์เดิมทุกครั้งที่เซฟ
   เมื่อเกิน 540 วินาทีจะแจ้งเตือนแต่ยังเดินต่อ; กด `f` เพื่อจบรอบก่อนหรือ STOP เพื่อหยุดได้
   หากมุมก้มไม่พอ ระบบถอยเพื่อเล็งได้สูงสุด 14 ซม. เฉพาะเมื่อแผนที่ยืนยันทางเปิดด้านหลัง
   และ ToF ด้านหลังอ่านได้อย่างน้อย 400 มม. หลังเล็งจะกลับตำแหน่งเดิม;
   หากถอยไม่ได้หรือยังใกล้เกินมุมก้มของ gimbal จะข้ามการยิงป้ายนั้น
   การยิงยังต้องผ่านเกณฑ์ล็อกเป้าเดิม หากล็อกไม่สำเร็จจะไม่ยิง
   ไฟฐานล้อเป็นสีแดงระหว่างตัวรถเดิน/เลี้ยว/ปรับตำแหน่ง และเป็นสีขาวตอน gimbal หมุนหรือสแกน
   ไฟบน gimbal และ blaster ดับเพื่อไม่ให้แสงรบกวนกล้อง
3. หากต้องการสำรวจโดยไม่ยิง กด `m` / MAP ONLY แทน
4. `f` จบรอบสำรวจและยกเลิกการเริ่มยิงเป้าใหม่; `x` / Space หยุดการทำงาน
5. สถานะ `shot` เก็บแยกต่อป้ายและบันทึกลงแผนที่ จึงไม่ยิงซ้ำเมื่อกลับมา
   ช่องเดิมหรือโหลดแผนที่เดิม รอบยิง `Enter` และรอบซ้อม `d` ใช้สี/รูปทรง
   ที่เลือกใน GUI ด้วย และข้ามป้ายที่ยิงไปแล้ว

ตัวเลือกสี/รูปทรงเปลี่ยนได้เมื่อหุ่นว่างเท่านั้น แต่ละรอบใช้ค่าที่เลือกตอนเริ่ม
สนามจำลอง 4×4 เดิมมีป้ายแดงรูปสี่เหลี่ยม จึงไม่ยิงด้วยเงื่อนไขวงกลมสีแดง
ให้เลือกสี/รูปทรงที่มีในสนามจำลองหากต้องการทดลองยิง

หากกล้องล็อกกลางป้ายแล้วจุดตกของกระสุนยังเยื้อง ให้ยิงทดลองจากระยะที่ต้องการ
แล้วสร้าง `shot_calibration.json` ที่โฟลเดอร์โปรเจกต์ เช่น

```json
{"samples": [
  {"distance_m": 0.45, "miss_right_cm": 2.0, "miss_up_cm": -1.0},
  {"distance_m": 0.85, "miss_right_cm": 0.5, "miss_up_cm": -1.5}
]}
```

ค่าบวกของ `miss_right_cm` คือกระสุนตกขวากว่ากลางเป้า; ค่าบวกของ `miss_up_cm`
คือตกสูงกว่าเป้า ใช้ค่าเฉลี่ยของหลายครั้งที่ระยะเดียวกัน โปรแกรมแปลงระยะคลาด
เป็นมุมชดเชยและคั่นค่าระหว่างระยะที่วัดไว้โดยอัตโนมัติ ไฟล์นี้จะโหลดตอนเปิดโปรแกรม;
ตัวเลขในตัวอย่างเป็นเพียงรูปแบบไฟล์ ไม่ใช่ค่าที่วัดจากหุ่นจริง

GUI จัดลำดับเป็น เลือกเป้า → สำรวจ → ใช้แผนที่ ปุ่ม EXPLORE ONLY (`m`) สำรวจโดยไม่ยิง และ SHOW ROUTE OPTIONS เปิดตัวเลือกเส้นทางขั้นสูง หากตำแหน่งไม่แน่นอน ปุ่มเริ่มภารกิจจะปิดจนจัดหุ่นกลับจุดเริ่มต้นแล้วกด CONFIRM START (`h`) ปุ่ม STOP อยู่ด้านล่างและกดได้ตลอดเวลา

การเข้ากลางช่อง: เริ่มชะลอเร็วขึ้น จำกัดความเร็วช่วง 12 ซม. สุดท้ายที่ 0.08 m/s ลดความเร็วต่ำสุดเป็น 0.04 m/s และสั่งเบรกเมื่อเหลือ 8 มม. เพื่อเผื่อการไหล หลังเบรกต้องได้ตำแหน่งใหม่ที่อยู่ภายใน 3 มม. จากจุดอ้างอิงติดต่อกัน 3 ช่วง (ช่วงละ 0.15 วินาที) หากข้อมูลค้างหรือยังไม่หยุดภายใน 2 วินาทีจะ fault เกณฑ์ยืนยันกลางช่องยังเป็น ±2 ซม. ต้องตรวจผลจริงตามพื้นและน้ำหนักหุ่น

## Grid SLAM จาก SLAM_si08 (รวมกับสำรวจและหาเป้า)

`maze_shooter.py` เปิด Grid SLAM เป็นค่าเริ่มต้น โดยนำ particle filter จาก
`SLAM_si08/exploration/grid_slam.py` มาไว้ที่ `robo_app/maze/grid_slam.py`
และใช้ร่วมกับแผนที่ เป้า กล้อง และรอบยิงของโปรเจกต์นี้ ไม่มีการเรียกโปรแกรมจากโฟลเดอร์ต้นฉบับ
รอบสำรวจใช้ Dijkstra บนสถานะช่องและทิศหันหน้า โดยคิดต้นทุนเดิน 1 ต่อช่อง
และต้นทุนเลี้ยว 0.8 สำหรับ 90° หรือ 1.5 สำหรับกลับหลัง เลือกช่องที่ยังไม่เคยไป
ซึ่งมีต้นทุนรวมต่ำ และให้โบนัสเล็กน้อยกับเป้าที่ตรงตัวกรองแต่ยังยิงไม่ครบ
ในโหมด EXPLORE + FIRE จึงกลับไปหาเป้าใกล้ ๆ โดยไม่อ้อมไกลเกินไป
เดินเฉพาะทางที่ยืนยันว่าเปิดแล้ว และคำนวณใหม่หลังสแกนแต่ละช่อง
รอบยิงไปจุดหมายด้วย A* ตามเดิม

รันจริง:

```bash
.venv/bin/python maze_shooter.py
```

ระบุขนาดสนาม ช่องเริ่มต้น X/Y และทิศ 0=N, 1=E, 2=S, 3=W แล้ววางหุ่นกลางช่องนั้น
กด EXPLORE ONLY (`m`) เพื่อทดลองสำรวจโดยไม่ยิงก่อน ระบบสแกน ToF แนวราบ 4 ทิศ
เพื่อแก้ตำแหน่งก่อนก้มหัวตรวจเป้า จึงไม่ใช้ระยะที่ลำแสงชนพื้นเป็นระยะสำหรับ SLAM
เมื่อ SLAM แก้ช่องของหุ่น โปรแกรมทิ้งเส้นทางเก่าและวางเส้นทางใหม่
รอบยิงยังใช้ตัวเลือกและข้อมูลเป้าเดิม โดยสแกนระบุตำแหน่งหลังเดินแต่ละช่องเช่นกัน

```bash
.venv/bin/python maze_shooter.py --sim
.venv/bin/python maze_shooter.py --load
.venv/bin/python maze_shooter.py --no-slam
```

`--no-slam` ใช้ระบบเดิมและรองรับกรณีไม่รู้ช่องเริ่มต้น (ตารางเผื่อ)
แผนที่ตารางเผื่อที่บันทึกไว้ต้องใช้ `--load --no-slam` หรือสำรวจใหม่โดยระบุช่องเริ่มจริง
ค่า SLAM บนภาพกล้องและ log คือสัดส่วนน้ำหนักของอนุภาคที่เลือกช่องนั้น
ไม่ใช่ค่าความแม่นยำที่สอบเทียบกับสนามจริง

หากค่าความมั่นใจต่ำกว่า 70% โปรแกรมหยุดสแกนซ้ำหนึ่งครั้ง และยอมไปต่อเมื่อได้ช่องเดิม
พร้อมความมั่นใจอย่างน้อย 70% หากอ่าน ToF ใช้ได้ไม่ถึง 3 ทิศจะลองสแกนซ้ำแล้วหยุดเมื่อยังอ่านไม่ได้
การอ่าน ToF แต่ละทิศต้องมีตัวอย่างใหม่อย่างน้อย 3 ค่าในช่วงวัด
ก่อนเปิด GUI โปรแกรมยืนยันว่าโหมดหุ่นเป็น `FREE` และกล้องเริ่มส่งสตรีมสำเร็จ
เมื่อ Body เคลื่อนเกิน 4 ซม. หรือหมุนเกิน 8° ระหว่างสแกน โปรแกรมจะหยุด
ก่อนขับแต่ละช่อง โปรแกรมวัด ToF แนวราบเฉพาะด้านที่แผนที่ยืนยันว่ามีกำแพง
ถ้าเห็นกำแพงสองด้านจะเทียบระยะซ้าย–ขวาเพื่อสไลด์เข้ากลาง; ถ้าเห็นด้านเดียว
จะปรับเฉพาะเมื่อได้ค่า offset ของ ToF จากขอบสนามแล้ว ระยะสไลด์ไม่เกิน 6 ซม.
ค่าที่ผิดช่วงหรือแผนที่ไม่ยืนยันกำแพงจะข้ามการปรับ หลังวัดจะเช็กว่าตัวรถไม่ขยับ/หมุน
และแก้มุมหัวก่อนเดินต่อ การขับตรงจะชะลอเมื่อมุมคลาดตั้งแต่ 6° และหยุดเมื่อถึง 18°
หรือสตรีม IMU ค้าง
หาก odometry หลังหยุดคลาดจากกลางช่องเกิน 2 ซม. แต่ผนังปลายช่องยืนยันอยู่ในแผนที่
โปรแกรมวัด ToF ใหม่ขณะนิ่ง และยอมรับการถึงช่องเมื่อระยะตรงกับค่ากลางช่องที่เรียนไว้
ภายใน 20 มม. โดย odometry ขาดไม่เกิน 12 ซม. จากนั้นให้ SLAM ตรวจช่องซ้ำ
ถ้ายืนยันไม่ได้จะหยุดโดยไม่สร้างกำแพงหรือถอยกลับอัตโนมัติ ต้องวางหุ่นที่ START
แล้วกด CONFIRM START (`h`) ก่อนเริ่มใหม่

ถ้า ToF ด้านหน้าทำให้หยุดก่อนกลางช่อง โปรแกรมจะหยุดล้อและตรวจ ToF ใหม่ขณะนิ่งหนึ่งครั้ง
เมื่ออ่านได้ว่าระยะด้านหน้าพอสำหรับเดินส่วนที่เหลือพร้อมระยะเผื่อกันชน จึงเดินต่อช้า ๆ
หากยังมีสิ่งบัง ค่า ToF ขาด หรือ odometry ยืนยันกลางช่องไม่ได้ จะหยุดและให้รีเซ็ตตำแหน่ง
การเบรกฉุกเฉินที่ใกล้กว่า `BUMPER_MM` ยังคงหยุดทันที

แผนที่เก็บ `slam.method`, `slam.pose_confidence`, `slam.tof_wall_offset_mm`,
`slam.tof_offset_calibrated`
และ `pose_uncertain` เพิ่มเติม โดยยังเก็บรายการเป้าและสถานะยิงเดิมครบ
Particle filter สร้างใหม่หลังยืนยัน START; ไม่บันทึกอนุภาคทั้งหมดลงไฟล์
การโหลดแผนที่จึงเริ่มจาก START ที่ผู้ใช้วางหุ่นและตรวจยืนยันเอง

ส่วนที่นำมาคือ Grid SLAM, การตรวจตำแหน่งก่อนหาเป้า, การปรับกลางช่องจาก ToF
และขอบเขตความปลอดภัยของมุมหัวระหว่างวิ่ง ส่วนการหยุดกลางช่องและ Sharp IR
ยังใช้ของโปรเจกต์นี้ หน้าจอ browser, telemetry และตัวประเมิน accuracy
จาก SLAM_si08 ยังไม่ได้รวม
การทดสอบจำลองไม่ยืนยันความแม่นยำบนหุ่นจริง ต้องตรวจช่องเริ่มและการสแกนทีละช่องกับหุ่น
